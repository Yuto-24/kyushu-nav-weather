# 九州 NAV LOG 用気象補助資料：要件・配置検討

更新日：2026-11-22 JST  
状態：ユーザーは、代表レグの中点を含む固定疑似セクターから一つの表を選び、その代表レグ全体の平均風を読む方式を承認した。初版を見て、現行のセクター分割と表の基本形式を「基本的にはこれでOK」とし、×印の削除、不要な説明文の削減、1 min当たりの燃料使用量の追加、ヘッダーと表配置の見直しを指示した。現在の10区画・代表集合・既存気象値を維持し、数字を探しやすく読みやすい紙面へ改訂する。基本構成の了承を、精度や閾値の運用承認とは扱わない。

最新の確定事項：区画は表を探す補助であり、風・地形の分布境界ではない。表の値は一つの代表レグ全長の距離加重平均とし、疑似区画の面積平均や複数レグの合成平均へ置き換えない。親子区域や「レグ全体が入る最も狭い区域」を探す方式は引き続き不採用。代表中点の×は紙面に表示しない。不要なセカンダリラベルや説明文を避け、レイアウトに対応関係を説明させる。方式は第16節、最新の紙面改訂は第17節と `analysis/pseudo_sectors/` に記録する。第5〜6節、第10〜15節は過去の段階の記録で、当時の未承認・不採用条件を現在の中点方式へ無条件に適用しない。

紙面例は2026-11-20の過去の実MSMで、09:00／14:00の各A4一枚を作る。現在予報の定期取得、05:00／10:00締切の定期処理、MSM取得失敗時のGSM等による補完、公開API・閲覧サービスは未実装。

## 1. 目的

宮崎空港からの手書きNAV LOG作成を補助するため、固定疑似セクターと対応する代表レグの上空気象・SR22巡航速度を事前に集計し、九州の白地図上へ表として配置する。予定レグの中点から参照する表を選ぶ。予報対象時刻ごとに画像1枚、A4用紙1枚へ印刷する。

## 3. ユーザー指定の代表経路

先頭のRJFMを除き、提供された順序を保持している。「枕崎／野間岬」は選択経路であり、両方を順番に通る意味にはしない。

| 目的地 | 代表経路 |
| --- | --- |
| RJFO | UMK → 小丸 → 鶴御崎 → 祝島 → GC (VREP) → RJFO |
| RJFG | 南郷大島 → 枕崎／野間岬 → 西之表 (VREP) → RJFG |
| RJFT | 米ノ津駅 → 新玉名駅 → 植木 (VREP) → RJFT |
| RJFK | 都井岬 → 枕崎／野間岬 → 加治木 (VREP) → RJFK |
| RJFU | 獅子島 → 玉名 → 長田 (VREP) → RJFU |
| RJFS | 産島 → 八女IC → 大牟田 (VREP) → RJFS |

RJFMから米ノ津駅・獅子島・産島までは直行と確認済み。地形に沿わせるための迂回点や、指定されていない中間変針点は追加しない。セクター境界を通過しても、それは経路上の新しい変針点を意味しない。

経路の順序・直行の意図と、地図へ置く座標の精度は別に扱う。`route_reference_draft.json` の座標は配置・概略被覆を検討するための参照位置であり、新たに取得した地図サービス等の座標も、ユーザーが航法用の正確な変針点として承認したものではない。枕崎／野間岬の選択を展開した検査用の経路は計8本となる。

## 4. 流用できる既存実装と、今回の差分

NavMateのMSM/GSM取得・水平／高度／時刻補間、SR22性能表、CAS/TAS換算を再利用できる可能性が高い。具体的な公開APIと新しい処理からの呼び出し方は実装前に確認する。

現行のNavMateは、MSMの通信障害・配信不足をGSM切替の理由としていない。全MSM候補がモデル・時刻・領域・高度の仕様範囲外の場合に切り替える。このため、今回の資料に必要な「MSMが取得できない場合もGSMで補完」は、既存選択方針をそのまま流用しても満たさない。取得ライブラリの再利用と、資料用の選択方針は区別する。

現行のNavMateは計画MSL高度を性能計算のPAとして扱い、QNH補正をしない。今回もこの近似を使うことがユーザー確認済みである。気象を取得・表示する高度はft MSLとし、性能計算のPAには同じ数値を入力する。モデル気圧から別途PAを導出する方式へは、この作業で変更しない。

通常MSM気圧面GPVの出力は3時間間隔。09:00 JSTは出力時刻に一致する。14:00 JSTは同一Runの12:00と15:00の気温・風成分等を時間補間する設計案とする。風向角度の算術平均は用いない。異なるRunの12:00と15:00を組み合わせない。

## 6. 初期の模擬値によるA4配置試験（履歴）

当時の配置試作はA4横（297×210 mm）。中央へ地図を置き、左右へ5表ずつ、計10表を配置した。表は9高度×5列、1表56×34.5 mm、数値本文8.5 pt。高度は上から9500、8500、7500、6500、5500、4500、3500、3000、2500 ftの順とした。

出力は09:00版・14:00版を各1ページとする2ページPDF、および各予報時刻1枚の300 dpiグレースケールPNG。区域番号、引出線、区域境界、空港をモノクロで区別する。印刷時はA4横の実際のサイズを使い、拡大縮小で文字寸法を変えない。

すべての気象・CAS・TAS数値は文字幅・配置を確認する仮データであり、気象予報でもSR22性能表を使った計算結果でもない。対象日・初期時刻・生成時刻も試作の表示欄である。運用APIや実データ取得・計算が完成したことを示す成果物ではない。

### 当時の配置の幾何検査

`layout_measurements.json` に、以下の配置・被覆検査を記録した。

- 10本の引出線すべてで、地図側の接続点が自区域内にあり、表に隠れていない。
- 引出線同士の交差は0件。他の表を横切る引出線は0件。
- 参照位置27点が、いずれかの区域に含まれる。
- 枕崎／野間岬の選択を展開した8経路について、紙面上の直線区間を計4,080点でサンプルし、区域外の点は0件だった。

これらは紙面配置と概略被覆の検査である。航法経路の正確さ、地形クリアランス、全領域の完全な被覆・非重複、気象の均質性、実際のGPV抽出・補間を検証したものではない。

### デジタル出力の確認結果

- PDFの2ページとも297×210 mmであることを確認した。
- 09:00版・14:00版のPNGは各3508×2481 px、300 dpi、グレースケールのLモードで出力した。
- 各ページに10表があり、各表の最上段9500 ft・最下段2500 ftを確認した。
- 罫線と数値の重なりを修正し、Popplerでレンダリングした2ページと白黒2値化プレビューを目視確認した。デジタル画像での切れ・重なりは認めなかった。
- 地図上の接続位置10か所の露出、引出線の交差がないこと、指定地点を含む地図範囲を確認した。Natural Earthで祝島の輪郭が省略される制約は残るため、祝島は参照点として表示している。

実機でのA4印刷・コピーは未実施。デジタル画像の確認結果は、個々のプリンターや複写機での再現性まで確認したものではない。

### 旧配置での観測

旧15区域・A4縦の試作では、表を区域内へ完全に収めると本文が1.53〜7.2 ptとなり、15表中9表が7 pt未満だった。その後、広域化と区域外配置の許容を受けて今回の10区域・A4横へ改めた。旧配置の結果は、その区域案と配置方法に限る観測であり、A4への配置一般が不可能という結論ではない。

## 7. まだ確定していない事項

全6方面共通の九州1枚、区域外配置、モノクロ、MSL＝PAの性能計算近似、西向き3区間の直行、南郷大島、高度の行順に加え、疑似区画の中点参照と代表レグ平均の方式は確認済みであり、再質問の対象にしない。現在は実データによる試作段階で、運用版へ進む際に次を仕様化する。

| 課題 | 決める内容 |
| --- | --- |
| 代表値の運用上の評価 | 現行10区画と表の基本形式はユーザーが基本了承し、今回の配置改訂の基準として維持する。任意の審査レグへの代表性、残る区間別差、運用上の許容値は別に評価する |
| ばらつき印 | 代表レグ内部の風ベクトルの変動と、同じ表を参照する別レグ平均との差の印を区別し、意味・閾値を決める。逆向きの風による相殺、弱風時の風向差を考慮する。試作の5 kt等を合意済みの許容基準にしない |
| 最低有効サンプル | 地形・鉛直補間条件で除外した後、代表レグの最低何点・何割の距離を必要とするか。有効な少数点だけで全レグを代表できることを自動的に保証しない |
| 補完単位と初期時刻 | 画像全体を単一モデル／Runにするか、欠けた区域・高度だけ補うか。後者で初期時刻が混在する場合は、初期時刻欄の意味と補完元の表記を合わせて決める |
| 運用構成 | 公開先、定期処理の実行基盤、MSMの候補Run探索範囲・保持期間、締切前の再試行、両モデル取得不能時の表示・既存画像の保持 |

モデル選択は確認済みのMSM優先を維持し、対象日時を含む正常データを使う。旧Runの年齢だけでGSMを優先する条件は追加しない。過去の別予報時刻の画像を当日予報として扱わない。

表示の詳細として、風向は真方位で吹いてくる方向、速度はkt、気温は℃を提案済み。風向の10度四捨五入は確定事項として反映済み。風速・気温・CAS/TASの表示精度と、ばらつき・地形・取得失敗の記号は最終仕様に明記する。試作のT・?・*は表示例であり、確定したUI文言ではない。

静的PNG＋JSONを定期生成し、閲覧ページから参照する方式が初期案。運用中のNavMate変更、本番公開、通知、自動化タスク作成は未実施。

## 8. 位置データの再利用で得た知見

以下は今回の座標確認での観測として残す。一般規則へ拡張しない。

- NavMate現行mainの一般ポイントCSVとチェックポイントCSVはヘッダーのみであり、指定された全地点を検索できるマスターは存在しない。
- 大分GCは現行VREPのGOLF COURSEを採用。旧経路KMLと座標が異なるため、古いKMLを無条件に優先しない。
- 鶴御崎は往路／帰路KMLで同名・異座標だった。今回は小丸→鶴御崎→祝島の往路にある点を配置参照として使用。
- 玉名と新玉名駅、既存経路の米ノ津と米ノ津駅を同一座標へ置き換えない。
- 大島は日南市南郷大島と確認済み。地図上では島の参照位置を使い、南端の鞍埼灯台を島中心の代わりにしない。島の同定と正確な航法変針点の確定は別である。
- `route_reference_draft.json` で新たに採用した米ノ津駅・新玉名駅・南郷大島・枕崎・産島等の座標は、出典を保持した地図用参照位置である。枕崎の市街地参照位置、島の参照位置、IC入口等を、ユーザーの確定した航法変針点と扱わない。
- 西向き3区間の直行はユーザーの確認事項として保持する。地図用の参照座標を結んだ紙上直線の被覆確認は、経路に中間点を追加する理由にも、航法精度を保証する根拠にもならない。
- 空港・VREPの既存マスターも含め、今回の位置確認は現行AIPに対する運用上の照合を完了したという意味ではない。

操作は「予定レグの中点を見る → 中点が入る固定疑似区画を選ぶ → 同じ記号の表で使用高度を読む」。区画は一層で重ならず、日付・予報時刻・高度によって変わらない。レグの端点や途中が他の区画を通っても、レグ全体の包含や通過距離割合を調べて選び直さない。親子区域、全レグ包含、最大通過割合、紙上での複数風の合成は今回の参照操作に用いない。

### 表に入れる値と区画の役割

各表には、対応する**一つの代表レグ全長**から複数地点をサンプリングした距離加重平均u/v・気温を入れる。疑似区画内の面積平均、複数代表レグの合成平均、代表中点での一点抽出は行わない。レグが疑似区画を横切る位置は集計範囲を分ける位置ではなく、計算上のサンプル点も新たな変針点ではない。

地形・鉛直補間条件による除外がある場合は、有効距離率と除外理由を保持する。「全長平均」は、無効な値や地形以下の値まで含めることを意味しない。気温平均と使用高度から、固定したNavMateのSR22巡航条件でCAS/TASを計算する。MSL＝PAの承認済み近似を維持する。

地図上の丸英字は表への引出線が読みやすい区画内位置へ移せる。代表中点の内部座標と丸英字は別に管理する。初版では代表中点の×と操作・意味の説明を紙面へ表示したが、ユーザーは×を表示しないことと、不要な説明を削ることを明確に指示した。現行紙面では中点座標を内部に保持し、英字・配置・引出線で表との対応を示す。固定経路線・レグ参照表も載せない。最新表示は第17節に従う。
